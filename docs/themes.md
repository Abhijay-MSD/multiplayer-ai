# Themes

Multiplayer AI's room can be drawn in several themes. Each one is an independent
design made for this project. They are not affiliated with, derived from, or
endorsed by any AI provider, and they do not reuse any product's logos, fonts,
colors, icons or wording. Signal Room is the default and the house style
described in PRD section 20.

| Theme | Character | Live signal |
|---|---|---|
| `signal-room` | Warm, studio-like. The default. | Flat waveform |
| `plain` | Neutral grays, one centered column, bubbles, a left rail that collapses. | Three dots that pulse |
| `paper` | Warm off-white, serif replies, a reading column, a card composer. | A thin line that breathes |
| `horizon` | Bright and airy, large corners, a tall composer with mode chips. | A soft wave with one small gradient |

Every theme has a light and a dark mode. The mode follows the system setting
unless the viewer picks System, Light or Dark in the theme switcher.

## How it works

- `<html>` carries `data-theme` (which theme) and `data-mode` (`light` or
  `dark`). `data-mode-pref` holds the viewer's choice (`system`, `light`,
  `dark`).
- A short inline script in `index.html` (generated by `web/vite.config.js`)
  sets all three before the first paint, so there is no flash of the wrong
  theme. It requests nothing: the fonts are bundled.
- Switching at runtime (`themes/ThemeProvider.jsx`) loads the new theme's
  fonts first, then changes the attributes. No reload.
- The choice is saved in `localStorage` (`multiplayer-ai:theme`, `multiplayer-ai:mode`)
  through `themes/preferences.js`. That file has a marked seam for saving it to
  a user profile once accounts exist.
- The marketing page at `/` always uses `signal-room`. Themes apply to the app.

## Files in a theme

```
web/src/themes/<id>/
  theme.json      required  id, label, one-line blurb, order, signal, fonts
  tokens.css      required  colors, type, radius, shadow for light and dark
  structure.css   optional  layout changes the tokens cannot express
```

`web/src/themes/base.css` holds the defaults every theme inherits. A theme only
sets what it wants to change.

### `theme.json`

```json
{
  "id": "signal-room",
  "label": "Signal Room",
  "blurb": "Warm and studio-like. The default.",
  "order": 0,
  "signal": "wave",
  "railCollapsible": false,
  "fonts": {
    "families": ["Fraunces Variable", "Hanken Grotesk Variable", "Spline Sans Mono Variable"]
  }
}
```

- `signal`: `wave`, `softwave`, `dots` or `line`. See "Live signal" below.
- `railCollapsible`: lets the people rail collapse on desktop.
- `fonts.families` lists the family names the switcher waits for before applying
  the theme. They are the names the bundled font packages declare, which end in
  "Variable" (`src/themes/bundled-fonts.js` imports them). To add a font, add its
  package there, pin it exactly, and check its license first (only OFL, MIT, ISC or
  BSD) and that it has no install script. Nothing may be loaded from another host:
  `web/qa/external-requests.spec.js` fails if a page asks for one.

### `tokens.css`

Two blocks per mode, selected by `[data-theme="<id>"][data-mode="light|dark"]`,
plus one block per theme for fonts. Required color tokens:

| Token | Use |
|---|---|
| `--bg`, `--bg-sunk`, `--surface`, `--tint` | page, recessed, raised and tinted surfaces |
| `--text`, `--text-muted` | text |
| `--border`, `--border-strong` | hairlines, hover and selected borders |
| `--accent`, `--on-accent` | agent mode, primary action, and the text on it |
| `--control` | controller state (the ring, "Driving", "Take control") |
| `--link`, `--danger`, `--focus` | links, errors and stopped states, focus ring |
| `--signal-a` (and optional `--signal-b`) | live signal color; `--signal-b` is a second gradient stop |
| `--identity-1` to `--identity-5`, `--on-identity` | participant colors and the text on them |

Also set `--font-ui`, `--font-display`, `--font-mono`, and optionally
`--font-agent` (the face for agent replies). Radius, shadow and the
transcript's shape are tokens too (`--radius`, `--agent-bg`,
`--directive-bg`, `--directive-align`, `--comment-*`, `--stage-max`,
`--shadow-composer`, and so on). `base.css` lists all of them with defaults.

Run `node scripts/check-contrast.mjs` to check the WCAG AA ratios of the
token pairs for every theme and mode.

### `structure.css`

Use it only when tokens are not enough, for example moving the rail or
reshaping the composer. Components expose `data-part` attributes
(`room`, `header`, `rail`, `composer`, `entry`, `agent-body` and others) and
`data-kind` on transcript entries. Select them under your theme:

```css
@media (min-width: 721px) {
  [data-theme="my-theme"] [data-part="room"] { /* ... */ }
}
```

Scope layout rules to `min-width: 721px`. Below that, every theme shares the
phone layout (the people rail becomes a drawer).

## Live signal

`LiveSignal` shows the agent's state with the same four labels in every theme:
"Agent is idle", "Agent is working", "Step limit reached", "Last step failed".
The state comes from `sessions.agent_working` and the status events, not from
the theme. The theme chooses the drawing through `signal` in `theme.json` and
its colors through `--signal-a`, `--signal-b` and `--danger`. Every variant has
a still version under `prefers-reduced-motion`.

## Adding a theme

1. Copy `web/src/themes/signal-room/` to a new folder and change `id`.
2. Edit `theme.json`, then `tokens.css`. Add `structure.css` only if needed.
3. Run `node scripts/check-contrast.mjs` and the QA run (`npm run test:e2e`
   in `web/`).

The registry finds the folder on its own: no import to add, and the switcher
lists it.

## Fonts

The fonts are bundled with the app (the `@fontsource-variable` packages, all OFL-1.1,
imported in `src/themes/bundled-fonts.js`), so nothing is fetched from another host.
Every face is declared up front with `font-display: swap`, and the browser downloads
a font file only when text uses it. The switcher asks for the next theme's fonts
before applying it, waiting at most 1.2 seconds.

| Theme | Families |
|---|---|
| `signal-room` | Fraunces, Hanken Grotesk, Spline Sans Mono (variable) |
| `plain` | Figtree |
| `paper` | Newsreader, Source Sans 3 |
| `horizon` | Plus Jakarta Sans |

`plain`, `paper` and `horizon` use the system monospace for code, so they
download one or two families each.

## Checks

From `web/`:

- `npm run check:copy` fails on banned phrases and on AI product names in
  `web/src` and `docs/`.
- `npm run check:contrast` checks WCAG AA ratios of every theme's token pairs.
- `npm run test:e2e` builds the app with the test pages on, then runs
  Playwright: screenshots and axe for the room, the name screen and the landing
  page across themes, modes and widths (images land in `web/qa/.results/screenshots/`, which git ignores, so a test run never changes a tracked file),
  the no-flash and no-layout-shift checks, room behavior in every theme, and a
  long-transcript measurement.
- `npm run qa:update-screenshots` is the one command that replaces the tracked
  review images in `web/qa/screenshots/`.
- `npm run qa:marketing-shots` renders the landing page's theme screenshots and
  story crops from the recorded session into `web/public/marketing/`.
